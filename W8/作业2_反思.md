# 作业2：关于 README 中“已知问题”为什么要诚实写的反思

在工程规范中，README里的“已知问题”绝不是自曝其短，而是体现开发者极其重要的工程素养与责任心。首先，诚实写出当前限制（例如未启动Ollama会导致本地模式报错），能极大降低使用者的排错与摸索成本，避免别人在不知情的情况下反复踩坑，浪费宝贵的调试时间。其次，任何软件都有其技术边界，坦诚说明局限性（例如本地模型的效果与响应速度不如云端模型），反而能建立起使用者对产品的信任，让大家明确知道在什么具体的业务场景下使用最合适。如果为了追求表面完美而藏着掖着，看似光鲜，却极易在实际交付和正式演示时引发灾难。在真实的项目开发与迭代中，透明、真诚、不藏雷，永远比虚假的完美更重要。
